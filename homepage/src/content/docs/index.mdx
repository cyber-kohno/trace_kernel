## 数行で済むはずの処理に、準備が多すぎる。

<div class="overview-demo">

## 入力データを、コードからそのまま使える形に。

CSV、ログ、対象ディレクトリ、固定値などを、ワークスペース上の**コンテキスト**として登録できます。<br></br>
登録したコンテキストはMonacoエディタに型情報として注入され、TypeScriptから補完付きで参照できます。<br></br>
入力ファイルを読み込むための定型コードを書かずに、処理本体から始められます。

    <p class="context-call">呼び出し例：<code>$env.DEST_DIR</code></p>

  <article class="context-card">

    <p class="context-call">呼び出し例：<code>$resource.userData</code></p>

  <article class="context-card">

    <p>指定したディレクトリ配下から、複雑なフィルタ条件（例：<code>.git</code>フォルダを除外し、<code>*.java</code>のみ抽出）に合致するファイルだけをGUIで直感的に抽出。数万のファイル群でも遅延ロードで安全に走査・解析が可能です。</p>
    <p class="context-call">呼び出し例：<code>$dataset.workspace</code></p>

## 実行結果を、GUIに直接表示する。

<div class="terminal-free-section">
  <div class="terminal-free-copy">
    <p>
      プログラムの実行結果は、アプリ内の出力パネルに直接表示されます。<br></br>
      Trace Kernelでは、<code>$</code>で始まる独自APIを使って、出力、進捗表示、テーブル表示などをプログラムから扱えます。<br></br>
      単純なテキストは<code>$print</code> / <code>$println</code>で出力し、長時間の処理は<code>$state</code>で進捗や現在処理中のファイル名を表示できます。<br></br>
      出力を用途ごとに分けたい場合は<code>$channel</code>で複数のストリームを作成し、テキストやテーブルとして結果を確認できます。
    </p>
    <ul class="terminal-feature-list">
      <li>
        <strong>状態表示 (<code>$state</code>)</strong>
        <p>大量ファイルの走査や変換処理では、完了までに時間がかかることがあります。<code>$state</code>を使うと、プログレスバーやモニターを表示し、処理件数や現在処理中のファイル名をログとは別に確認できます。</p>
      </li>
      <li>
        <strong>複雑な出力 (<code>$channel</code>)</strong>
        <p><code>$channel</code>を使うと、ログ、集計結果、エラー一覧などを別々のストリームに分けて出力できます。テーブルストリームを使えば、集計結果を行と列の形で確認できます。</p>
      </li>
    </ul>

## ストレージを散らかさない

<div class="storage-clean-section">
  <div class="storage-clean-copy">
    <p>
      Trace Kernelでコードを実行するために、作業ディレクトリへ<code>package.json</code>やコンパイル後の<code>.js</code>ファイルを作る必要はありません。
      実行に必要なコードや設定は、アプリ内のワークスペースで扱われます。コードを動かすために、物理的な作業ディレクトリや実行用ファイルを用意する必要はありません。
    </p>
  </div>

## 通常の開発環境との違い

| 通常の開発環境 | Trace Kernel |
| --- | --- |
| プロジェクトを作成してコードや設定ファイルを管理する | 物理ファイルを作らず、アプリ上のワークスペースでリソースとプログラムを管理する |
| npm install やビルド設定を用意する | アプリ内の実行環境でTypeScriptを実行する |
| 入力ファイルを読み込むボイラープレートを書く | GUIで登録したログやCSVが、プログラム上の補完候補として使える |
| プログラムを実行するためにコマンドを叩く | 実行ボタン、またはエディタ画面のショートカットキーで即実行する |

より詳しい考え方は、[通常の開発環境との違い](/overview/philosophy/)で説明しています。

<div class="overview-callout">
  Trace Kernelは、VS CodeやNode.jsプロジェクトの置き換えではありません。開発環境を組むほどではないが、手作業では曖昧になりやすい処理を、TypeScriptで明示して実行するための環境です。
</div>

## Trace Kernelでできないこと
Trace Kernelは、アプリやライブラリを開発するためのIDEではありません。<br></br>
ログ解析、データ変換、ファイル調査のような技術作業を、TypeScriptでその場で処理するための作業環境です。<br></br>
そのため、以下のような本格的な開発プロジェクトの管理や運用は対象外です。

<ul class="not-supported-list">
  <li><Icon name="close" />Webアプリやライブラリを開発するための本格的なプロジェクト管理</li>
  <li><Icon name="close" />npmパッケージを自由に追加して構成するNode.js開発</li>
  <li><Icon name="close" />長期間運用するサーバーアプリケーション</li>
  <li><Icon name="close" />複数人でGit管理する通常のソフトウェア開発プロジェクト</li>
</ul>

</section>
