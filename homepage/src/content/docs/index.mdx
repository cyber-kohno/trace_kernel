## ファイル読み取りのコードは書かなくていい

Trace Kernelでは、設定やリソースなどの前提情報（**コンテキスト**）と、処理本体（**ワーク**）をひとつの**ワークスペース**内で集中管理します。GUI上で定義したコンテキストは、Monacoエディタに自動的に注入され、強力な型推論と補完とともに即座に呼び出せます。

<div class="context-card-grid">
  <article class="context-card">
    <div class="context-card-icon"><Icon name="setting" /></div>
    <h3>env（環境変数）</h3>
    <p class="context-card-subtitle">パスや設定値の定数化</p>
    <p>ファイルの出力先ディレクトリなどをGUI上で変数（例：<code>DEST_DIR</code>）として定義します。プログラムに直書きしないためエスケープミスを防ぎ、環境ごとのパス変更もGUIからワンタッチで行えます。</p>
    <p class="context-call">呼び出し例：<code>$env.DEST_DIR</code></p>
  </article>

  <article class="context-card">
    <div class="context-card-icon"><Icon name="document" /></div>
    <h3>resource（静的リソース）</h3>
    <p class="context-card-subtitle">テキストやCSVを直接オブジェクト化</p>
    <p>GUIのテキストエリアにCSVやTSVを貼り付け、「CSV to JSON」パースを指定するだけ。実行時には自動でJSONオブジェクトの配列としてパースされるため、面倒な文字列分割処理を書くことなく、即座にループ処理へ移行できます。</p>
    <p class="context-call">呼び出し例：<code>$resource.userData</code></p>
  </article>

  <article class="context-card">
    <div class="context-card-icon"><Icon name="list-format" /></div>
    <h3>dataset（動的データセット）</h3>
    <p class="context-card-subtitle">ローカルPC内の大量ファイルを安全にバインド</p>
    <p>指定したディレクトリ配下から、複雑なフィルタ条件（例：<code>.git</code>フォルダを除外し、<code>*.java</code>のみ抽出）に合致するファイルだけをGUIで直感的に抽出。数万のファイル群でも遅延ロードで安全に走査・解析が可能です。</p>
    <p class="context-call">呼び出し例：<code>$dataset.workspace</code></p>
  </article>

## プログラムからGUIを制御

<div class="terminal-free-section">
  <div class="terminal-free-copy">
    <p>
      プログラムの実行結果は、GUI上に直接反映されます。<br></br>
      標準出力するだけの<code>$print</code>, <code>$println</code>関数を始め、<br></br>
      GUIアプリならではの利便性の高い様々なAPI群（<code>$</code>で始まる独自関数）が用意されています。<br></br>
      APIを用途に応じて使い分けることで、問題をスムーズに解決することができます。
    </p>
    <ul class="terminal-feature-list">
      <li>
        <strong>状態表示 (<code>$state</code>)</strong>
        <p>「いつ終わるかわからないループ処理」は、<br></br>数行追加するだけで、GUI上にリアルタイムなプログレスバーやモニター（解析中のファイル名表示など）を表示することができます。<br></br>
        ログを汚染せずに状態を把握することができます。</p>
      </li>
      <li>
        <strong>複雑な出力 (<code>$channel</code>)</strong>
        <p>プログラム上でストリームを動的に作成し、<br></br>
        複数のログを別々に出力することができます。<br></br>
        出力結果はGUI上でチャンネルを切り替えながら直接確認できます。<br></br>
        また、テキストだけでなく、整った表（テーブル）形式のストリームとして表示・整理することも可能です。<br></br>
        単一のテキスト出力では手に余る問題にも対応できます。</p>
      </li>
    </ul>

## 通常の開発環境との違い

| 通常の開発環境 | Trace Kernel |
| --- | --- |
| プロジェクトを作成してコードや設定ファイルを管理する | 物理ファイルを作らず、アプリ上のワークスペースでリソースとプログラムを管理する |
| npm install やビルド設定を用意する | アプリ内の実行環境でTypeScriptを実行する |
| 入力ファイルを読み込むコードを書く | GUIで登録したログやCSVが、プログラム上の補完候補として使える |
| プログラムを実行するためにコマンドを叩く | 実行ボタン、またはエディタ画面のショートカットキーで即実行する |

より詳しい考え方は、[通常の開発環境との違い](/overview/philosophy/)で説明しています。

<div class="overview-callout">
  Trace Kernelは、VS CodeやNode.jsプロジェクトの置き換えではありません。開発環境を組むほどではないが、手作業では曖昧になりやすい処理を、TypeScriptで明示して実行するための環境です。
</div>

## Trace Kernelでできないこと
Trace Kernelは、日常で発生する小さな問題を、<br></br>
プログラムを使ってスムーズに解決するための道具として設計されています。<br></br>
アプリ開発のためのソフトではありません。

<ul class="not-supported-list">
  <li><Icon name="close" />Webアプリやライブラリを開発するための本格的なプロジェクト管理</li>
  <li><Icon name="close" />npmパッケージを自由に追加して構成するNode.js開発</li>
  <li><Icon name="close" />長期間運用するサーバーアプリケーション</li>
  <li><Icon name="close" />複数人でGit管理する通常のソフトウェア開発プロジェクト</li>
</ul>

</section>
