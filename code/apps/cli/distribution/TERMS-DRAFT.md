2026-10-15。製品方針を確認するための未確定案。現在の配布ZIPには同梱せず、承認済みの利用許諾文として扱わない。

## 1. 対象と利用

本案はTrace Kernel DesktopとTrace Kernel CLIを対象とする。両アプリは、TypeScriptで記述したWorkを実行し、結果を出力するためのソフトウェアである。

Freeは個人作業・業務に利用できる。Professionalは有効なライセンスキーにより追加機能を利用できる。DesktopとCLIには共通のライセンス検証と機能区分を適用する。CLI単独での利用も対象に含める。

外部ツール、データ、生成したWorkや出力物に対する第三者の権利・利用条件は、それぞれに従う。

## 2. Professionalの利用単位【要判断】

**提案A：利用者単位。** 1契約につき指定した1名が利用でき、その本人の複数PCでDesktop・CLIを利用できる。本人が管理するバッチ・タスクスケジューラによる自動実行も対象に含める。複数名によるライセンスキーの共用は認めない。

代案Bは端末単位、代案Cは組織単位。いずれも、キーをどのOSユーザーから読み取るかという実装上の探索仕様とは区別する。

サーバーの共有実行基盤で他の利用者に実行機能を提供する場合や、顧客へサービスとして提供する場合の契約単位は、正式規約で別途定める。提案Aの「本人の自動実行」を、組織全員の共有利用と同義にしない。

## 3. 複製・配布【要判断】

**提案A：契約範囲内のバックアップ・組織内配置を許可し、組織外への再配布や別製品への同梱は個別許諾とする。** キーを含めず、利用条件・OSS表示等を保持する。

代案Bは未改変の公式ZIPに限り組織外への再配布も許可、代案Cは公式サイトからの取得に限定する。

本体に関する配布条件により、同梱OSSがそれぞれの条件で許諾する権利を制限しない。

## 4. キーと実行

キーは利用者が適切に管理する。CLIのキー探索順位は、明示ファイル、同じOSユーザーのDesktop保存済みキー、Freeである。保存場所やキーをコピーできること自体は、他の利用者への利用許諾を意味しない。

Workはファイル更新・外部プログラム実行・通信を行う場合がある。対象、権限、実行内容を利用者が確認する。`--check`はWorkの実行を伴わない事前検証であり、入出力の成功を保証しない。`--commit`はVFSの適用を制御し、直接I/Oや外部processまで無効化するものではない。

## 5. OSSと外部プログラム

同梱OSSの条件は`THIRD-PARTY-NOTICES.txt`、`licenses/`、該当するsource案内に記載する。上流の著作権・許諾条件は保持する。

利用者のWorkが起動する外部プログラムやアクセスするサービスは、利用者が別途準備し、それぞれの条件に従う。
