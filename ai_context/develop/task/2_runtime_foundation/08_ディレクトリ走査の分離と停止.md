# ディレクトリ走査の分離と停止

2026-10-12。第4段階の継続。対象はscan_directory、Workerの遅延dataset検索、編集画面の走査監視。
CLIの追加、packages/cratesへの移動、Excelパーサーへの停止対応は行っていない。

## 責務の分離

- `apps/desktop/src-tauri/src/scan.rs`: DTO・フィルター・実ファイル走査。Tauri、AppHandle、Emitterへ依存しない。進捗通知と停止確認を関数として受け取る。
- `apps/desktop/src-tauri/src/scan_commands.rs`: Tauriの受付、実行IDの照合、blocking task起動、任意の進捗イベントを担当する。
- `blocking_io.rs`: run_checkedを追加した。Operationを実際のblocking taskに保持したまま、実処理から共通の停止確認を呼べるようにした。既存ファイル15コマンドのrunは同じ経路を利用する。
- `dataset-scan-result.ts`: 走査結果からdatasetの相対targetsへ変換する、UI/Tauri非依存の小さな関数を抽出した。現在の保存形式である先頭のバックスラッシュは維持する。

共通crateへの移動に備えた境界をDesktop内に作る段階であり、CLIがDesktop内部を参照する構成ではない。

## 結果とエラー契約

- 深度制限のルートを0とする。制限に達したディレクトリでは子ディレクトリへの下降だけを止め、そのディレクトリ内のファイルとノードは残す。以前は子ディレクトリを見つけると親全体をNoneにし、結果が欠落していた。
- 除外されたルートは実際の名前と空のchildren配列で返す。空のディレクトリはファイルではない。以前のname=root/children=nullという代替ノードを廃止した。
- ルートがドライブ等でfile_nameを持たない場合はパス文字列を名前に使い、unwrapでpanicしない。Workerの相対パス生成はルート名を切り刻まず、ルート直下から組み立てる。
- 不存在、ファイルをルートにした要求、read_dir/列挙/metadata失敗をResultで返す。途中結果を正常値へ変えない。
- UTF-8へ正確に表せない名前はエラーとする。損失変換で別のファイル名として結果へ混ぜない。
- 条件はRegexとして事前コンパイルする。regex::escapeで*以外を文字どおり扱い、コンパイル失敗もResultで返す。compiled_patternのOptionとunwrapは廃止した。
- directory包含条件のAND、file包含条件のOR、除外優先、次の深度にdirectory包含条件があると現在の階層のファイルを除外する規則は、既存動作として維持した。この規則の意味を今回別仕様へ変えていない。
- ディレクトリリンクへは下降しない。ファイルリンクは従来どおり対象にできるが、リンク先metadataが失敗した場合はエラーにする。ルートとして明示されたリンクの扱いは変更していない。

走査はファイルシステムの原子的なsnapshotではない。並行変更による一覧の変化、metadata確認と利用間のTOCTOU、リンク差し替えに対する防御は保証しない。アクセス権限やsandboxの境界でもない。

## Workerと停止

1. worker_initを予約API生成・遅延dataset走査より前へ移動した。初期化失敗時は走査とユーザーコードを実行しない。
2. NativeIoPolicyにscan_directoryを追加し、WorkerSessionが現在実行のexecutionIdを束縛する。所有対象は既存18コマンドと走査の計19コマンドになった。
3. 存在しない/停止済みIDでは走査を開始しない。IDなし編集呼び出しへフォールバックしない。
4. 走査開始、各条件のコンパイル前、ディレクトリ到達、進捗通知後、各entry、結果返却前に停止確認を行う。停止はエラーとして返し、部分一覧を成功にしない。
5. Operationはblocking taskが所有する。worker_stop/disposeは、停止した実処理が終了してOperationを解放するまで待つ。既定Worker RPCの10秒タイマーだけでnative走査を切り離すことはしない。
6. dataset走査が失敗した場合はprepared/doneやVFSを返さない。他の走査が残っている場合も、WorkerSessionの既存終端処理が所有者の停止・終了待ちを行う。

停止確認は協調的なもの。すでに始まったOSのmetadata/read_dirやRegexのコンパイルそのものを強制中断できない。OS操作が戻らなければ停止確認も待ち続ける。新たな全体deadlineや停止待機上限は追加していない。

## 編集画面の進捗

- 編集呼び出しにはscanIdを発行し、progressへ同じIDを付ける。別スキャンのイベントは受け取らない。Worker走査にはscanIdを付けないので、編集画面へ余計な進捗を送らない。
- イベント送出は補助的な通知であり、送出失敗を走査失敗/panicへ変換しない。結果とエラーの正本はIPC応答。
- progress_doneへの依存を除き、成功・失敗・監視登録失敗のいずれでもfinallyでリスナーを解除し、検索中状態を解放する。
- ルートのUIパスは要求されたrootPathを使い、名前を重ねて連結しない。ドライブのルートでも子ファイルのパスを正しく組み立てる。
- 画面破棄やdataset切替ではAbortSignalで監視を解除する。リスナー登録の完了が遅れた場合も解除し、旧結果・エラー表示・進捗を抑制する。結果反映は開始時のdatasetと選択indexを照合する。

**編集画面のAbortSignalは監視解除であり、native走査の停止命令ではない。** 編集呼び出しは従来互換の実行IDなし処理で、画面を閉じた後もnativeが完了まで動く場合がある。Worker実行のCancelは実行所有者を閉じるため、協調停止と終了待ちの対象になる。
progress_done削除とscanId追加は内部IPCの変更。FrontendとRustを同じ版で更新する必要がある。Workのユーザー向けAPIやtrkの形式は変えていない。
