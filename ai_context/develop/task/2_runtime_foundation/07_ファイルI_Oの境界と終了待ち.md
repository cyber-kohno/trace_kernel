# ファイルI/Oの境界と終了待ち

2026-10-12。第4段階の継続。CLIの追加やpackages/cratesへの移動は行っていない。
対象はfile_systemの15コマンド。ディレクトリ走査scan_directoryやExcelパーサーは対象外。

この文書は実施時点の記録。後続の `08_ディレクトリ走査の分離と停止.md` でscan_directoryの分離・実行所有・協調停止を追加した。Excel等は引き続き未対応。

## 分離した責務

- `apps/desktop/src-tauri/src/file_system.rs`: ファイル処理、DTO、encoding、実ファイルを使う回帰テスト。Tauri command/State/AppHandleに依存しない。
- `apps/desktop/src-tauri/src/file_system_commands.rs`: Tauriの受付。実行IDがあればAppStateからOperationを取得し、共通のblocking処理へ渡す。IDなしの編集・トランザクション確認/適用の呼び出しは維持する。
- `apps/desktop/src-tauri/src/blocking_io.rs`: Tauriへ依存しないblocking処理の実行とOperationの寿命管理。OS処理をTokioのblocking poolへ送る。
- `native-io-policy.ts`: WorkerSessionとWorkerInvokeが参照する所有対象の共通リスト。ファイル15コマンドと既存のprocess/HTTPの3コマンドが対象。

Rustの共通crateへ移せる境界を現行フォルダ内に作った段階であり、CLIからDesktop内部を直接参照する構成にはしていない。

## エラー契約

- read_fileはResultを返す。ファイルがない・開けない・読めない場合に、エラー文を本文の文字列として成功返却しない。成功時の文字列、UTF-8/Shift-JIS指定は維持する。
- exists_pathはtry_existsを使用する。単なる不存在はfalse、存在確認自体のI/O失敗はエラーにする。
- glob_pathは列挙中のエラーを無視せず返す。途中結果だけを成功として扱わない。
- read_dirは各要素のmetadata失敗を返す。is_dirのfalseへ隠さない。壊れたリンクや走査中に消えた要素でも、部分一覧を正常値にしない。
- 削除の存在確認はmetadataへ統一する。不存在と他のI/O失敗をPath::existsのfalseへまとめない。削除種別と空ディレクトリ限定の規則は維持した。
- tailTextのlineCount=0は、従来どおり空文字列を返す。ファイル存在確認まで追加する変更はしていない。
- DatasetChooseRowの既存読込呼び出しにもcatchを追加し、UI側で拒否されたPromiseを放置しない。

失敗の扱いが変わるため、エラー文字列の成功返却・globの部分結果・metadata失敗をfalseとして利用していたWorkでは例外が出るようになる。意図的に例外をcatchして継続する仕様は維持している。
文字コード不正の厳格検出、検証から更新までのTOCTOU、原子的な保存、ロールバックは今回追加していない。

## 停止・完了の契約

1. WorkerSessionが対象呼び出しのexecutionIdを現在実行のIDへ束縛する。ユーザーAPIの引数形式は変えない。
2. Tauri受付で存在しないID・停止済みIDを拒否する。IDを指定したのに見つからない場合、IDなし処理へフォールバックしない。
3. Operationは呼出元のFutureではなく、実際のblocking taskが所有する。IPC呼出元が破棄されても、待機中/開始済み処理が所有件数から消えない。
4. blocking処理開始前に停止が観測された場合、ファイル処理を実行せず返す。blocking poolの待機中に停止された処理も同じ規則に従う。
5. すでに開始した処理は実終了まで待つ。worker_stop/disposeが、ファイル処理を残したまま成功することを防ぐ。終了後も停止状態なら成功値をWorkerへ返さない。
6. task内でpanicした場合は、ファイルへの影響が途中かもしれないというcleanup失敗を所有者へ残す。件数0だけで安全な終了と判定しない。
7. 対象コマンドは既定のWorker RPC 10秒タイマーを使わない。通信だけが時間切れになり、OS更新が裏で続く状態を避ける。他のコマンドの既定タイマーは維持する。
8. done到着時に対象IPCが未完了なら、停止確認後にunfinished native I/Oとして失敗にする。VFSをトランザクション確認へ渡さない。

**OS操作の強制中断・巻き戻しの保証ではない。** 開始済みの保存・コピー・削除等は、Cancel後にも処理が終わるまで副作用が発生し得る。停止処理はその完了を待つ。
glob/read_dir/tailのループ途中の協調停止チェックはまだ入れておらず、コマンド全体の前後で停止を判定する。create_dir_all/remove_dir_all等も複数のOS操作になり得る。
ネットワーク共有等でOS操作が返らない場合、停止確認も待ち続ける。成功扱いで抜ける代替タイムアウトは設けていない。

IDなしの編集やトランザクション適用はWorker実行停止と別の寿命を持つ。Worker完了時に閉じた実行所有者へ、後続のGUIトランザクションを誤って登録しないための互換境界であり、アクセス制御・sandboxの境界ではない。
アプリ全体の終了管理や、将来の共通WorkExecutionServiceからtransaction適用を所有する設計は別途必要。
