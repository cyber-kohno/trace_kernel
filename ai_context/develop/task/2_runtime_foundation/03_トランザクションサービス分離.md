# トランザクションサービス分離

2026-10-12。共通化の構成方針の第2段階。
CLIやJS実行エンジンの追加ではなく、既存Desktop内で責務と依存方向を整理した。

## 配置と責務

```text
apps/desktop/src/app/
  contents/detail/program/runtime/transaction/
    transaction-model.ts       命令、検証結果、適用結果
    transaction-io.ts          ファイル操作の契約
    transaction-verify.ts      注入されたI/Oでの検証
    transaction-service.ts     計画・状態・実行結果を所有するセッション
  infra/tauri/transaction-io.ts Tauri commandと文字コード変換
  contents/detail/program/ui/tx/
    util/tx-executor.ts         Desktop用のセッション生成と既存GUI型の互換窓口
    util/tx-plan-normalize.ts   VFSから命令への変換と既存GUI型の互換窓口
    ui/TxDialog.svelte         サービス状態から表示用行・進捗への変換
```

- サービス・検証処理はSvelte、ストア、DOM、Tauri、GUIの型を参照しない。
- 共通命令の型をUIから移し、GUI側の型エイリアスで移行時の変更範囲を抑えた。
- I/Oは成功時にresolve、失敗時にrejectする。サービスが検証・適用の失敗結果へ変換する。
- readText/saveTextの文字コード変換はDesktopアダプター側。サービスはTauri DTOやencoding-japaneseを参照しない。
- 旧UI内の検証・適用実装は削除し、二重実装を残していない。
- packages/cratesへの移動はまだ行っていない。サービスの依存は同じディレクトリ内の型・検証処理と、既存の純粋なPathUtilのみ。

## セッションの契約

```text
idle -> verifying -> verification-failed -> verifying（再試行可能）
                  -> committing -> succeeded / commit-failed（再試行不可）
```

- create時に命令と更新元のメタデータをコピー・freezeする。外部から入力計画を書き換えても実行計画は変わらない。
- 検証・適用中の同時runは拒否する。失敗しても適用段階に入ったセッションは再実行しない。
- runは全体結果を返す。getSnapshotで各操作の検証・適用結果を取得できる。
- 操作結果の配列は入力順を保持する。実際の適用は従来の優先順位で行う。
- completedCountは適用を試みた件数。committedCountは成功件数。skippedはcompletedCountに含めない。
- 通知は任意で同期。画面がなくても実行できる。通知側の同期例外で適用処理や結果を変更しない。非同期処理を通知内で起動する場合の例外処理は利用側の責任。
- 通知済みスナップショットは後から変化しない。計画・状態・結果は読み取り専用で提供する。
- GUIはサービスの状態を既存のverify/commit表示に変換する。表示用行をサービスへ渡さない。

## 保証を拡張していない点

前段階と同じく、全件の検証にerror/warningがあれば更新しない。
適用失敗で後続を停止するが、成功済みの操作は戻さない。
今回の分離は原子的保存・競合の完全防止・複数ファイルのロールバックを追加するものではない。

セッションの内部状態はUIから独立したが、Desktopでの生成・寿命の管理はまだTxDialogにある。
画面破棄時の処理寿命、全体のcancel/dispose、永続的な適用記録は次の実行基盤整備で扱う。
パス規則は既存のWindows中心の仕様を維持した。OSごとの互換性はJSホストの検証と合わせて確認する。
