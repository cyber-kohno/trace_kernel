# 命名統一残差一覧

## 現状

`.ts` / `.d.ts` の命名は、原則 `kebab-case` へ統一済み。

`app/src` 配下で命名規約の観点から大きく問題になる `.ts` は、現時点ではほぼ解消している。

## 意図的に残すもの

- `worker.ts`
  - Web Worker のエントリポイントであり、現時点では役割が単純で問題なし
- `global.ts`
  - 役割が単独かつ短い。将来 `global-store.ts` や `global-api.ts` に分けるなら再検討
- `types.d.ts`
  - TypeScript の宣言ファイルとして一般的な命名
- `+layout.ts`
  - SvelteKit の予約ファイル

## `.ts` 以外で残っている命名課題

- `.svelte` の PascalCase / typo
  - `MaintenanceMange.svelte`
  - `MDResourece.svelte`
  - `MDDataSet.svelte`
- 型名 / namespace 名の古い表記
  - `TxExecuter`
  - `DclChannel`
  - `StoreWorkspace`

補足:

これらはファイル名ではなく、識別子名の課題として残っている。
Phase 2 では無理に触らず、責務分割とセットで見直すほうが安全。

## `npm run check` 上の残差

命名起因の error は解消済み。

残っているのは warning のみ。

- `ChooseRecord.svelte`
  - `a` タグの a11y warning
- `OrderRow.svelte`
  - 未使用 CSS selector warning

## 結論

命名統一は、次の段階へ進んでよい状態に達している。

今後は:

1. `.ts` ファイル名の統一を前提として運用する
2. `.svelte` の typo は構造改善と一緒に直す
3. 識別子名の見直しは責務分割とセットで行う

次の主テーマは `workspace-store` 分割へ戻す。
